# ЛР2 — Обзор

**Тема:** «Потоки. Процессы. Асинхронность». Продолжение проекта
[Bookcrossing](../report/overview.md) (ЛР1). Код лежит в `lab2/` и
использует то же виртуальное окружение (`.venv`) и ту же базу данных
(`bookcrossing.db`), что и основное приложение.

## Что нужно было сделать

Согласно методичке, реализовать одни и те же вычисления **тремя
способами**: `threading`, `multiprocessing`, `asyncio` — и сравнить.
Задач две:

* **Задача 1 — CPU-bound.** Посчитать сумму чисел от 1 до N = 10¹³, разбив
  диапазон на равные куски.
* **Задача 2 — I/O-bound.** Спарсить несколько веб-страниц (получить
  `<title>`) параллельно и сохранить результаты в БД.

Обе задачи нужно было решить в **трёх файлах** — по одному на подход, и
на одинаковых данных сравнить время работы. Это позволяет наглядно
показать, где какой подход выигрывает и почему.

## Общие выводы

* Для **CPU-bound** кода в Python работает только `multiprocessing`.
  `threading` бьётся о GIL, `asyncio` — кооперативная многозадачность в
  одном потоке, и оба не дают реального параллелизма.
* Для **I/O-bound** кода `threading` и `asyncio` наоборот выигрывают: пока
  один запрос ждёт ответа сети, event loop / другой поток может отправить
  следующий. `multiprocessing` здесь работает, но проигрывает из-за
  накладных расходов на создание процессов.
